Automating the repetitive jobs on your PC

Which tasks are worth automating, which are not, and the tools already on your machine that handle most of them.

By Hasnain Butt Akhtar, founder and developer · 5 September 2026

Automation has a reputation for being either trivial or a programming project. Most of the genuinely useful cases sit between the two, take under half an hour to set up, and use tools that are already installed.

Deciding whether it is worth it

The honest test is simple arithmetic. If a task takes two minutes and you do it weekly, that is roughly ninety minutes a year. Spending three hours automating it is a loss, however satisfying.

Three things make a task genuinely worth automating:

It happens often. Daily or weekly, not twice a year.

The rules never change. Every file goes to the same place, every time. If you have to think about each case, automation will keep getting it wrong.

Forgetting it has a cost. This is the strongest reason of all. A backup that runs automatically is better than one you remember to do, not because it saves five minutes, but because you will eventually stop remembering.

And one that makes it a bad idea: if the task involves judgement, leave it alone. Deciding which photos are worth keeping, which emails matter, or which files are safe to delete are all things people try to automate and then quietly spend longer fixing.

What is already on your machine

Task Scheduler runs anything on a schedule: daily, weekly, at startup, or when you log in. It is not attractive but it is capable and it has been in Windows for decades. Search for it in the Start menu, create a basic task, and point it at a program or script. This is how you make a backup or a cleanup happen without you.

PowerToys is a free set of utilities from Microsoft, and two of its tools cover most day-to-day repetition. PowerRename does find and replace across hundreds of file names at once, with a preview before it commits. Keyboard Manager remaps keys and shortcuts. Both are worth the download on their own.

File Explorer handles bulk renaming more capably than people realise. Select a group of files, press F2, type a name, and Windows numbers them in sequence. Crude, but it takes three seconds.

Storage Sense, in the Settings app, clears temporary files and empties the recycle bin on a schedule without any setup beyond switching it on.

The jobs that repay the effort

  1. Backups on a schedule. The single highest value automation on any machine, for the reason given above. Set it once and stop relying on your memory.
  2. Sorting incoming files. If your Downloads folder is chaos, a rule that moves files by type into subfolders keeps it manageable with no ongoing effort.
  3. Batch renaming. Photos with camera names, documents with inconsistent prefixes, anything where you want a date at the front so sorting works. PowerRename does this with a preview, which means you can see exactly what will happen before it happens.
  4. Text you type constantly. An address, a bank detail, a standard reply, an email signature. A text expander turns a short trigger into the full text, and it saves more time over a year than almost anything else on this list.
  5. Format conversion in bulk. Resizing a folder of images for a website, or converting a set of videos. Doing thirty files by hand is tedious and error prone. Doing them in one operation is neither.

Click automation, and why it breaks

Tools that record your mouse and keyboard and replay them look like the answer to everything, and they have one serious weakness worth understanding before you rely on one.

They usually work by position. Click at these coordinates, then those. That holds until something moves: a window opens at a different size, an update rearranges a toolbar, you connect a second monitor, or a dialogue appears that was not there when you recorded. The automation carries on clicking regardless, now on whatever happens to be underneath.

That makes them fine for genuinely repetitive work in a program that never changes, and poor for anything important running unattended. If you use one, keep the sequence short, avoid recording anything destructive, and watch it the first several times.

Where a program offers a proper way in, such as a command line option or its own batch feature, that is always more reliable than clicking at it from outside.

Doing it safely

Do it by hand first, several times. You cannot automate a process you have not fully understood, and the edge cases only appear once you have met them. What happens when a file with that name already exists? When the folder is empty? When the network drive is not connected?

Test on copies. Point the automation at a duplicate folder until you are confident. This is not excessive caution. A rename that goes wrong across two thousand files is genuinely difficult to undo.

Make it visible. Have it write a short log, or leave a file with a timestamp, so you can tell it ran. Automation that fails silently is worse than no automation, because you stop checking.

Never automate deletion. Move to a holding folder instead, and clear that out yourself occasionally. It costs a little space and removes the only outcome you cannot reverse.

Start with one task. Pick the thing you do most often that annoys you most, automate just that, and live with it for a fortnight before adding another. People who try to automate everything in one weekend generally end up with a collection of half-working scripts they no longer trust, which is worse than where they started.
